# Procurement Analytics

แดชบอร์ดวิเคราะห์ความเสี่ยงการจัดซื้อจัดจ้างภาครัฐ จากข้อมูลสัญญา 10,174 รายการ
(ปีงบประมาณ 2569 · 77 จังหวัด · มูลค่ารวม 28,716,369,657.38 บาท)

## การใช้งาน

ต้องเปิดผ่านเว็บเซิร์ฟเวอร์ เพราะหน้าเว็บโหลดข้อมูลด้วย `fetch` ซึ่งเบราว์เซอร์ไม่อนุญาต
เมื่อเปิดไฟล์โดยตรงจากดิสก์

```bash
python -m http.server 8000
```

แล้วเปิด <http://localhost:8000>

## การสร้างข้อมูลใหม่

`data/data.json` เป็นผลลัพธ์ที่สร้างจาก `raw_data.csv` ไม่ใช่ไฟล์ที่แก้ด้วยมือ
เมื่อข้อมูลต้นทางเปลี่ยน ให้สร้างใหม่ด้วย

```bash
python tools/build_data.py --verify
```

`--verify` จะตรวจค่าที่ทราบแล้วประมาณ 17 รายการ เช่น จำนวนระเบียน มูลค่ารวม
จำนวนแถวที่ parse พิกัดได้ และจำนวน hit ของกฎสำคัญ หากตัวเลขใดเพี้ยนไปจะแจ้งทันที

ต้องมี `pandas`, `numpy`, `networkx`

## โครงสร้าง

```
index.html            หน้าเว็บและโครงของแท็บ
css/style.css         สไตล์
js/util.js            จัดรูปแบบ สถิติพื้นฐาน วันที่ไทย ส่งออก CSV
js/rules.js           เครื่องมือประเมินความเสี่ยง R1-R17 และการตั้งค่าที่ปรับได้
js/analytics.js       HHI, เบนฟอร์ด, IQR, หน้าผาราคา, เครือข่าย, อนุกรมเวลา
js/charts.js          ตัวห่อ Plotly
js/tablesort.js       เรียงลำดับตารางเมื่อคลิกหัวคอลัมน์
js/app.js             ชั้นแสดงผลและการเชื่อมต่อ
tools/build_data.py   ETL จาก raw_data.csv เป็น data/data.json
raw_data.csv          ข้อมูลต้นทาง (แก้ไขไม่ได้)
data/data.json        ผลลัพธ์จาก ETL (สร้างใหม่ได้เสมอ)
```

หลังแก้ไฟล์ใน `js/` หรือ `css/` ให้เพิ่มเลขใน `?v=` ท้าย `<script>` และ `<link>`
ใน `index.html` เพื่อให้เบราว์เซอร์โหลดไฟล์ใหม่แทนการใช้ของเก่าที่แคชไว้

## สถาปัตยกรรม

ETL ทำเฉพาะสิ่งที่ต้องทำนอกเบราว์เซอร์ ได้แก่ การแปลงข้อมูลดิบให้สะอาด
และการคำนวณตัวชี้วัดเครือข่ายที่หนัก (PageRank, Betweenness, Louvain)

ส่วนกฎความเสี่ยง HHI และการตรวจจับความผิดปกติทั้งหมด **คำนวณในเบราว์เซอร์**
จึงปรับเงื่อนไขและน้ำหนักของกฎได้สดจากแท็บ "กฎและการตั้งค่า"
โดยผลจะเปลี่ยนทันทีทุกแท็บ (ประเมินใหม่ทั้งชุดใช้เวลาประมาณ 150 มิลลิวินาที)
ค่าที่ตั้งไว้ถูกจำใน `localStorage` ของเบราว์เซอร์

## แท็บเครือข่าย

มีตัวกรองเฉพาะแท็บที่ทำงานต่อจากตัวกรองส่วนกลาง ได้แก่ หน่วยงาน · ผู้รับจ้าง ·
**กฎที่พบในคู่นั้น** · ระดับเสี่ยงสูงสุดของคู่ · จำนวนสัญญาต่อคู่ขั้นต่ำ · มูลค่าขั้นต่ำ
พร้อมสวิตช์ "เฉพาะคู่ที่พบสัญญาณ" และ "ตัดเลขภาษีที่ถูกปิดบัง"
ทุกตัวกรองซ้อนกันได้ และแถบสรุปด้านล่างบอกจำนวนคู่ โหนด และมูลค่าที่เหลืออยู่เสมอ

แสดงได้ 4 รูปแบบ: แผนภาพการไหล · ฟองอากาศ · ทรีแมป · **ตารางความร้อน**
(หน่วยงาน x ผู้รับจ้าง เลือกผู้เล่นที่มูลค่ารวมสูงสุดมาแสดง)

ตัวกรองเหล่านี้อยู่ใน `netFilteredEdges()` ของ `js/app.js` โดย `Analytics.networkEdges()`
เตรียมข้อมูลที่ต้องใช้มาให้ในแต่ละเส้นแล้ว (`rules`, `flagged`, `masked`, `max_risk`)
จึงไม่ต้องวนระเบียนซ้ำตอนกรอง

## แผนที่

หมุดแสดงได้ 3 รูปแบบ (กลุ่ม / รายจุด / ความหนาแน่น) และระบายสีได้ 6 มิติ
ผ่านตัวเลือก "ปักหมุดตาม" ได้แก่ ระดับความเสี่ยง · กฎที่พบ (เลือกกฎที่น้ำหนักสูงสุดของสัญญานั้น) ·
หมวดของสัญญาณ · วิธีจัดหา · ประเภทโครงการ · ช่วงมูลค่าสัญญา
คำอธิบายสัญลักษณ์สร้างจากข้อมูลที่แสดงอยู่จริง จึงเปลี่ยนตามตัวกรองเสมอ

เลือกพื้นหลังได้ 4 แบบ (สว่าง ถนน มืด ภาพถ่ายดาวเทียม) พื้นหลังมืดจะสลับสีชั้นซ้อนทับให้อ่านออก
ขนาดหมุดปรับตามมูลค่าสัญญาแบบ log ได้

**ไอคอนกลุ่มเป็นวงแหวนสัดส่วน** (conic-gradient) แสดงองค์ประกอบของกระจุกตามมิติที่เลือกอยู่
จึงเห็นได้ทันทีว่ากระจุกนั้นประกอบด้วยอะไรบ้าง ไม่ใช่แค่จำนวน
กระจุกที่สัดส่วนระดับวิกฤตสูงกว่าค่าเฉลี่ยของชุดที่แสดงอยู่ตั้งแต่เท่าตัวขึ้นไป (และมีอย่างน้อย 3 รายการ)
จะเต้นเบาๆ เพื่อดึงสายตา เกณฑ์นี้คำนวณจากข้อมูลที่กรองอยู่ ไม่ใช่ค่าตายตัว
เพราะสัดส่วนวิกฤตเปลี่ยนตามตัวกรองและค่าที่ตั้งในกฎ (ใช้เกณฑ์ตายตัวแล้วจะเต้นหมดหรือไม่เต้นเลย)
ผู้ที่ตั้งค่าลดการเคลื่อนไหวในระบบปฏิบัติการจะไม่เห็นการเต้นนี้

**คำอธิบายสัญลักษณ์กดสลับได้** คลิกที่กลุ่มเพื่อซ่อนหรือแสดงกลุ่มนั้นบนแผนที่
แถบสถิติจะแยกให้ชัดว่าจุดที่ไม่แสดงมาจากการซ่อนเองหรือจากการตัดตามเพดานการวาด

ปุ่ม "กรองเฉพาะพื้นที่ที่เห็น" ใช้กรอบแผนที่ปัจจุบันเป็นตัวกรองส่วนกลาง มีผลกับทุกแท็บ
และยกเลิกได้จากป้ายในแถบสรุปตัวกรอง ส่วนปุ่ม ⛶ เปิดแผนที่เต็มจอ

การเพิ่มมิติใหม่ให้แก้ที่ `COLOR_MODES` ใน `js/app.js` ที่เดียว โดยเขียนฟังก์ชัน `of(record)`
ที่คืน `{key, label, color}` สีของกลุ่มใช้ `categoryColor(index, total)` ซึ่งจะสร้างเฉดกระจายเท่ากัน
เมื่อจำนวนกลุ่มเกินชุดสีที่เตรียมไว้ 10 สี (เช่นกฎมี 17 ข้อ) เพื่อไม่ให้คนละกลุ่มได้สีซ้ำกัน

**ข้อจำกัดสำคัญ:** ชุดข้อมูลมีพิกัดเฉพาะงานจ้างก่อสร้าง 6,728 จาก 6,780 รายการ
ส่วนงานซื้อ จ้างทำของ เช่า ออกแบบ และที่ปรึกษา รวม 3,394 รายการ ไม่มีพิกัดเลย
แผนที่จึงไม่ได้แทนภาพรวมทั้งหมด ข้อความนี้แสดงอยู่ใต้แผนที่ในแอปด้วย

## ตารางอธิบายกฎ

แท็บ "กฎและการตั้งค่า" มีตารางอ้างอิงกฎทั้ง 17 ข้อ แสดง ชื่อ · คำอธิบายกฎ · ที่มา ·
การคำนวณ · จำนวนที่พบ เรียงลำดับได้ทุกคอลัมน์และส่งออก CSV ได้ (13 คอลัมน์ รวมมูลค่าที่พบ)

คอลัมน์ "ที่มา" ประกอบด้วยประเภทข้อมูล (จริงหรือสาธิต) ชื่อคอลัมน์ในชุดข้อมูลที่กฎนั้นใช้จริง
และเหตุผลที่ตั้งกฎ ข้อมูลส่วนนี้อยู่ใน `Rules.DOCS` ใน `js/rules.js` แยกจากตรรกะการประเมิน
เมื่อเพิ่มกฎใหม่ต้องเพิ่มรายการใน `DOCS` ด้วย

ทั้งเงื่อนไขและจำนวนที่พบในตารางอัปเดตตามค่าที่ปรับในแผงตั้งค่าด้านล่างทันที
กฎที่ถูกปิดใช้งานจะแสดงเป็นแถวจาง

## การเรียงลำดับตาราง

ทุกตารางเรียงลำดับได้โดยคลิกที่หัวคอลัมน์ คลิกซ้ำเพื่อสลับระหว่างน้อยไปมากและมากไปน้อย
คอลัมน์ตัวเลขเรียงตามค่า คอลัมน์ข้อความเรียงตามลำดับพจนานุกรมไทย และคอลัมน์วันที่เรียงตามเวลาจริง

`js/tablesort.js` ทำงานผ่าน event delegation ที่ระดับ document จึงครอบคลุมทุกตารางอัตโนมัติ
รวมถึงตารางในหน้าต่างรายละเอียดที่ถูกสร้างขึ้นภายหลัง

เซลล์ตัวเลขควรมี `data-sort` เป็นค่าดิบเสมอ (ใช้ตัวช่วย `numTd` / `moneyTd` / `pctTd` / `dateTd`
ใน `app.js`) เพราะข้อความที่แสดงถูกย่อ เช่น "6.19 พันล้าน" หากเรียงจากข้อความจะคลาดเคลื่อน
ส่วนคอลัมน์วันที่ให้เก็บ `data-sort` เป็นรูปแบบ ISO เพื่อให้เรียงตามลำดับเวลาได้ถูกต้อง
แม้จะแสดงผลเป็น พ.ศ.

ลำดับที่เลือกไว้จะคงอยู่เมื่อตารางถูกวาดใหม่จากการเปลี่ยนตัวกรอง โดยผูกกับ `U.onRender`
หากไม่ต้องการให้คอลัมน์ใดเรียงได้ ให้ใส่ `data-nosort` ที่ `<th>`

หมายเหตุ: การเรียงทำกับแถวที่แสดงอยู่เท่านั้น ตารางที่ตัดมาเฉพาะอันดับต้นจะระบุจำนวนไว้ที่หัวการ์ด

## ข้อควรทราบเกี่ยวกับข้อมูล

- คอลัมน์จังหวัด อำเภอ ตำบล ระบุที่ตั้งของ**หน่วยงาน** ส่วนพิกัดบนแผนที่มาจาก
  คอลัมน์ตำแหน่ง**โครงการ** ทั้งสองอย่างไม่จำเป็นต้องตรงกัน
- มีพิกัดจริง 6,728 จาก 10,174 แถว (66.1%) ที่เหลือไม่มีข้อมูลตำแหน่งในต้นฉบับ
- เลขผู้เสียภาษี 2,205 แถว (21.7%) ถูกปิดบังเป็นรูปแบบ `130990115xxxx`
  จึงถูกกันออกจากการวิเคราะห์เชิงตัวตน
- ชื่อผู้รับจ้างถูกทำให้เป็นมาตรฐานก่อนวิเคราะห์ (ยุบเว้นวรรคซ้อน ตัด prefix นิติบุคคลที่ซ้ำ)
  มิฉะนั้นบริษัทเดียวกันจะถูกนับเป็นคนละราย
- ชุดข้อมูลไม่มีจำนวนผู้เสนอราคาและวันปิดรับซอง กฎ R5 และ R6 จึงใช้ข้อมูลสังเคราะห์
  และ**ไม่ถูกนับรวมในคะแนนความเสี่ยงที่แสดง** ส่วนสาธิตทั้งหมดอยู่ในแท็บ "ส่วนสาธิต"

คะแนนความเสี่ยงใช้เพื่อจัดลำดับความสำคัญในการตรวจสอบ ไม่ใช่ข้อสรุปว่ามีการกระทำผิด
